User Guide

How to use VibeSafe Builder — from first prompt to published app

This guide walks through the whole journey: your free first build, picking how to pay, building and fixing an app, adding forms, payments and your own images, rolling back a version, and shipping it. Total time to your first working app: about 2 minutes.

01What VibeSafe Builder does

You describe an app in plain English, and VibeSafe Builder generates a complete, working app. For most requests that's a single self-contained HTML file, live in seconds. For a bigger idea, start a multi-file React project instead (§15): real components in separate files, with a path to a repository on GitHub and a deployment on your own Vercel account when it's ready for the world.

Either kind of app can grow beyond a page: shared data, its own sign-in for visitors, file uploads (§13), contact and waitlist forms (§14), and buy buttons through your own Stripe account (§09). And either way, every generation shows its cost before you commit to it, every change is a version you can roll back, and every build is scanned for common security mistakes before you can publish it.

Prefer to look before signing up? The interactive demo walks through the real workspace with no account and nothing to spend.

02Create your account

Every account, whether you'll bring your own API key or go Managed, starts by signing up at the builder. There are three ways in, all landing you in the same place:

  • Email and password: enter your name, email, and a password (at least 8 characters). We email you a link to confirm your address; click it, then come back and log in.
  • Continue with Google
  • Continue with GitHub: this is a sign-in only. It confirms who you are; it does not give VibeSafe Builder access to your repositories. Pushing code to GitHub is a separate connection you make later, with its own explicit permission screen (§16).

Your password is handled by Supabase Auth, our authentication provider. It's stored hashed, and we never see or handle it in plaintext ourselves. Forgot it? Use Forgot your password? on the sign-in screen.

03Your first build is free

Every new account gets one free build with no API key and no card. Just sign up and describe your app. You can publish the result to a live link like any other build.

To keep that free, the free build runs on a lighter AI model (Claude Sonnet 5) rather than Claude Opus 5, which both paid options use, so expect a less polished result. A failed attempt doesn't use up your free build. Once it's used, add your own Anthropic key or upgrade to Managed to keep going (§04). The free offer is limited and can be paused at any time.

04Choose how to pay: bring your key, or go Managed

Open ⚙ Settings in the left-hand rail. You have two ways to pay for generations:

A

Bring Your Own Key (free platform fee)

Paste an Anthropic API key (get one at platform.claude.com) into the Anthropic API key field, and click Check key to confirm it works before you build. It's stored only in your browser and sent with each build so it can reach Anthropic; we never store it on our servers. You're billed by Anthropic directly, at their standard rates, with no markup from us.

B

Managed plan ($15/month)

No API key needed: we cover up to $10/month of Anthropic usage on our own key. Click ⬆ Upgrade to Pro in the top bar (or in Settings) to subscribe through Stripe. If you've already paid, enter your email under Managed plan in Settings and click Email me a sign-in link.

In BYOK mode you can also set a session spend cap in the same Settings panel ($5 by default). Generation is blocked when a new request could push your successful-build spend past that number. The Managed plan has its own monthly budget instead (§20).

05Build your first app

The builder opens on one question: What do you want to build? Two ways to answer it:

  • Describe it: type something like "a habit tracker with streaks" or "an invoice generator" and press Enter (or the ➤ button). Use Shift + Enter for a new line. The suggestion chips under the box fill in a starting idea, and in Chrome and Edge the 🎤 button lets you dictate instead of typing.
  • Start from a template: click start from one of 16 templates for an instant v1 at zero generation cost, then keep chatting to customise it. You can browse them all, with live previews, on the templates page.

Generation streams in live; you'll see the assistant's one-line summary in the chat, followed by the app appearing in the Preview tab on the right.

06Agent modes: Auto, Build, Debug and Review

The Agent menu next to the message box decides what kind of job your request is. Leave it on Auto unless you want to force one:

  • Auto picks for you. Requests starting with "review", "audit" or "explain" go to Review; on an existing app, requests starting with "fix", "debug", "repair" or "diagnose" go to Debug; everything else is Build.
  • Build creates or changes features. This is the normal mode.
  • Debug focuses the AI on a problem you describe. It doesn't run your code or prove the fix works, so check the preview afterwards.
  • Review reads your app and writes a plain-English report in the chat, without changing any code or creating a version. It's model-assisted inspection, not a security certification or a test run.

All modes use the same model and count as normal usage, including against the free build. Debug and Review need an app to work on.

07Read the cost estimate and spend meter

Before you hit send, the composer shows an estimated cost for that specific request. After it completes, the top bar's build spend meter updates, but only for generations that actually produced a working app. If a generation fails (an invalid response, a refusal, a timeout), its cost shows separately as "failed (not counted)" and is never added to your spend total. This is the "failures don't count" principle from the homepage, made literal.

08Find your way around the builder

The rail on the left holds 📂 My Apps (§19), ＋ New Project, a light/dark switch, shortcuts to the main tabs, and ⚙ Settings. Click « Collapse to shrink it to icons. The line between the chat and the workspace can be dragged to give either side more room (or moved with the arrow keys; double-click it to reset).

The workspace on the right has these tabs. Some only light up for a multi-file React project (§15):

  • Preview: your app running live in a sandboxed frame, exactly as a user would see it. The 🚀 Publish button lives here.
  • Build Health: a combined pass/fail verdict from the security scan and Launch Check together.
  • Code: the full source, with Copy code and Download buttons.
  • Versions: every generation you've kept (§11).
  • GitHub: push a React project to a repository you own (§16).
  • Forms: create contact and waitlist forms and read what people send (§14).
  • Deploy: deploy a React project to your own Vercel account (§17).
  • Security: the scan results for the current version (§12).
  • Launch Check: loads your app in a real browser to catch console errors, crashes, and mobile-layout breaks that a static scan can't see.

09Refine: colours, rules, products and images

Once you have an app, a Refine panel appears above the message box. Everything in it is optional; you can always just ask for changes in plain English instead.

  • Brand style: pick a colour palette, or set your own background, primary, accent and text colours. The AI then builds, and keeps editing, with those colours instead of choosing its own. Choose "No preference" to hand it back.
  • Non-negotiables: write down what the app is for and up to 12 short rules that must stay true ("totals always include tax", "never ask for a phone number"). The AI reads them before every build, so a later change can't quietly undo an earlier decision, and it tells you in the chat when a request would break one.
  • Monetisation: sell something from your app. Create a payment link in your own Stripe account, paste it here with a product name and price (up to 5 products), and ask the AI for a buy button. Buyers check out on Stripe's own page and the money goes straight to you; we never handle the payment and no secret key is needed. Only links on buy.stripe.com or donate.stripe.com are accepted.
  • Brand assets: add your own logo, a hero image or a page background (PNG, JPEG, WebP or GIF). Images are resized in your browser, which also strips location data from photos, and are embedded when you preview, publish or download, so the file you own still contains them. SVG isn't accepted because it can contain scripts.

10Ask for changes, and what happens when a fix doesn't work

Keep chatting to iterate: "add dark mode", "the delete button doesn't work", "make it mobile-friendly". Each request only touches what you asked for. The model is instructed to preserve everything that already works rather than silently rewriting your app.

Doom-loop protection
If you ask for a fix twice in a row, a banner appears, "Same problem twice — switching strategy", and the next attempt re-diagnoses the issue from scratch instead of repeating the fix that already failed you.

11Version history and rollback

Every successful generation is saved as a version in the Versions tab, newest first, each showing its cost and a short note. Click any version to see a line-by-line diff against the one before it. Click Restore on any older version to make it current again. Nothing is lost; later versions stay in the list. Version history lives in your browser's localStorage (the most recent 20 versions, to stay within storage limits), so it survives a page reload but not a browser data wipe. Download the app if you want a permanent copy.

12The security scan and Launch Check

Every generation is checked against a set of common AI-coding mistakes: hardcoded API keys and secrets, eval() and other dynamic code execution, passwords written to localStorage, insecure requests, and more. The Security tab badge turns red if anything critical is found, with a plain-English explanation of each issue and how to ask the AI to fix it. The same check runs again, server-side, the moment you try to publish, so a bypassed or stale result in your browser can never slip a critical issue onto a public link. The full list is on the security page.

Launch Check goes further: click 🚀 Run Launch Check and the builder opens your app in a real headless browser, then reports console errors, crashes, files that failed to load, and layouts that overflow on a phone screen.

Deploying to your own Vercel account runs a related but separate check, the Publish Security Check (§17).

13Shared data, sign-ins and uploads inside your app

Most apps just save to the visitor's own browser, and that's what the AI does by default. When your request clearly needs more, it uses a built-in backend instead. There's nothing to set up, but these features only work once the app is published (§18); in the preview, the app falls back to saving locally or tells you to publish.

  • Shared data: ask for "a guestbook everyone can see", "a leaderboard" or "a list my whole team edits", and data is shared across every visitor and device, like a public whiteboard. Each app can hold up to 1,000 records.
  • Visitor accounts: ask for "parents log in and see only their own children" or "each user has their own saved items", and the app gets its own sign-up and log-in. Whatever a signed-in visitor creates is private to them unless the app marks it shared. These accounts belong to your app alone and have nothing to do with VibeSafe Builder accounts.
  • File uploads: ask for "attach a CV" or "add a photo to each listing", and visitors can upload PNG, JPEG, GIF, WebP or PDF files, up to 2MB each and 200 per app. The type is checked from the file's contents, not its name. Anyone with a file's link can open it, so don't use uploads for anything private.

14Forms: contact and waitlist

The Forms tab gives your app a working contact form or waitlist, with no form service to sign up for and no AI credits spent receiving submissions. You need a confirmed email address to create one.

1

Create the form

Give it a name and pick a type: Contact (name, email, message) or Waitlist (name, email). Tick Email new submissions to be notified at your account's address, and optionally send a confirmation to the person who submits, with a subject and message you write yourself.

2

Put it in your app

Click Add to build prompt and the AI wires the form into your app on the next build (the normal cost estimate applies), or Copy HTML to paste the snippet yourself.

3

Read submissions

Submissions land in the form's inbox, private to your account. From there you can refresh, Download CSV, pause the form, delete all submissions, or delete the form.

During the pilot each account can have 20 forms, receive 300 submissions per calendar month (UTC) and store 1,000 submissions, with up to 10 submissions per form per minute. An email marked "sent" means our email provider accepted it, not that it reached the inbox.

15Building something bigger: multi-file React projects

Everything above works the same way for a single-file app or a bigger project; the difference is what you start with. Click ⚛ New React project (in the chat, or from the empty state on the GitHub or Deploy tabs) instead of building a single page, and the builder generates a real project: components, hooks, and styles in separate files, assembled with Vite so it's a genuinely portable, buildable codebase. Starting one clears the current chat and versions, so save or download what you have first (it's also kept in My Apps, §19).

  • Targeted edits. Ask for a change and only the files that need it get rewritten. The rest of your project is left alone.
  • Visual editing. Click ✎ Edit visually, then click any element in the Preview to change its text, colour, background, font size and weight, alignment, padding, margin or corner radius directly, with undo and redo. No prompt, no cost.
  • Build status and preview links. The Preview shows whether the project builds, with any errors linked to the file they're in. 🔗 Share preview creates a link to a snapshot of the current build, so you can show someone your progress without publishing.
  • The same backend. Shared data, visitor accounts and uploads (§13) work here too.

Once you're in a React project, the GitHub (§16) and Deploy (§17) tabs light up.

16Connecting GitHub

The GitHub tab pushes a multi-file project into a real repository you own, so your code isn't trapped in the builder. This is a separate connection from signing in with GitHub (§02): signing in only confirms who you are, while connecting here asks for permission to create and write to repositories, shown on GitHub's own consent screen before anything happens.

1

Connect GitHub

On the GitHub tab, click Connect GitHub and approve the permission request. This is a one-time authorization per account.

2

Choose or create a repository

Pick an existing repo from the dropdown, or click + New repo to create one without leaving the builder.

3

Push

Click ⬆ Push to commit the current version to the repository, every file as one commit. ⬇ Pull brings changes made outside the builder back in, and the tab shows recent commits and lets you switch branches.

Disconnect any time from the GitHub tab. This removes the stored connection only; it doesn't touch anything already pushed to GitHub.

17Deploying to your own Vercel account

The Deploy tab puts a multi-file project live on your own Vercel account: your domain, your bill, and it keeps working whether or not you ever open this builder again. This is different from the built-in Publish button (§18): Vercel builds your project from real source with npm install and a real Vite build, the same as if you'd pushed it yourself.

1

Get a Vercel token

In Vercel, go to Settings → Tokens → Create Token. Under Scope, choose the single project you want to deploy to, not your whole account. A project-scoped token can only ever touch that one project; VibeSafe Builder never sees your other projects or their environment variables.

2

Connect it

Paste the token into the Deploy tab. It's encrypted before it's stored and never sent back to your browser; even the connection status only shows a masked hint like vcp_••••1234. Test connection checks it at any time.

3

Deploy a preview, or deploy to production

Deploy preview creates a new, unlisted deployment you can check before anyone sees it. Deploy to production replaces what's live at your project's main URL. You're asked to confirm before it runs.

Deployment Protection
Vercel projects are protected by default: visitors are asked to log in to Vercel before they can see the site. The Deploy tab tells you when this is on. Deploying still works either way; protection only affects whether the public can see the result.

Making it public. When you're ready for anyone to see it, click Make public… on the Deploy tab. This runs the Publish Security Check first: a scan of every file in your project for live credentials (API keys, database passwords, tokens) and other serious issues. A live credential blocks the change outright, with no way to override it; there's no legitimate reason to knowingly publish a working key, and it may already need rotating if it reached this point. You'll then be asked to type the project's name to confirm, since this is the one action here that exposes your app to the whole internet. After it runs, the builder checks that the site really is reachable by an outside visitor, rather than just trusting Vercel's response.

Making it private again. Make private… restores protection to exactly the mode it was in before, not a generic default, so if you'd only protected preview deployments, that's what comes back.

Every connect, deploy, and protection change is recorded in an activity log on the Deploy tab, and you can disconnect your Vercel account at any time. This only removes the stored token; your deployed sites stay online.

18Download or publish

↓

Download .html

From the Code tab. It saves the current version as a single portable file you can open locally, host anywhere, or hand to someone else, with your images and payment links already filled in. This is your app; there's no lock-in. It's installable to a phone's home screen out of the box.

🚀

Publish

From the Preview tab. It uploads the current version to a public link (/p/<id>) that anyone can open, install to their home screen and use offline. Publishing is blocked if the security scan finds a critical issue, or if the app still points at an image or buy button you haven't set up. Click Republish after later changes to update the same link.

Every published app carries a small ⚑ Report link so anyone can flag abuse; apps that break the rules can be taken offline. Both options work the same way for multi-file projects. For a real custom domain, or to host the project entirely under your own control, GitHub (§16) and Vercel (§17) are the paths built for that. See also the full deployment guide for every other option, from Netlify to Cloudflare Pages.

19My Apps, and where your work is saved

Your current project, its chat and its versions are saved automatically in this browser as you work, and come back when you reload. Click ＋ New Project to start something else; the app you were on is kept in 📂 My Apps, so nothing is lost by switching. Open My Apps to go back to any of them.

Because this is stored in your browser, it doesn't follow you to another device or browser, and clearing site data removes it. Download your app, push it to GitHub, or publish it if you want a copy that lives somewhere else.

20Managed plan budget and limits

The Managed plan's $10/month included usage is tracked automatically. If you hit that limit mid-month, generation pauses with a message telling you exactly how much you've used. You can wait for the next billing cycle, or switch to your own API key in Settings to keep going immediately. You're never charged overage. BYOK mode has no monthly cap beyond the session spend cap you set yourself.

21Troubleshooting

  • "Invalid API key" error: click Check key in Settings. A valid key starts with sk-ant-.
  • Asked for a key after one build: your free build is used. Add your own Anthropic key or upgrade to Managed (§04).
  • Generation blocked by the spend cap: raise the session cap in Settings, or stop there if you're near your intended budget on purpose.
  • Debug or Review won't run: both need an existing app. Build or open one first.
  • Lost my project: projects live in this browser's storage (§19). If you cleared browser data or switched devices without downloading first, it can't be recovered. Reload the same browser and profile to have it restored, or look in My Apps.
  • Shared data or uploads don't work in the preview: they only work once the app is published (§13).
  • Publish button is disabled or publishing is refused: you need at least one generated version, and the current version must pass the security scan. If it mentions an image or a payment link, check Brand assets or Monetisation (§09) and publish again.
  • Can't create a form: confirm your email address first, and check you're under the pilot limits (§14).
  • Make public is blocked: the Publish Security Check found a live credential or a serious issue. A live credential can't be overridden; remove it from the code and rotate it, since it may already be compromised. Other issues can be reviewed and, if you're sure, continued past.
  • Vercel connection doesn't work or can't change protection: reconnect with a fresh token if it was revoked or expired, and make sure it's scoped to the project you're deploying to. Some tokens can deploy but aren't permitted to change project settings; if Make Public says so, turn Deployment Protection off directly in your Vercel project settings instead.
  • GitHub push fails: reconnect GitHub from the GitHub tab. A token can expire or be revoked outside the builder.
  • Something else: see the FAQ, or email contact@vibesafebuilder.com.
